    1. NASA POWER — clima diario

    CORS: bloqueado en navegador

    Base del calendario agroclimático. Sin clave.

    📖 Cómo funciona
    • Endpoint: power.larc.nasa.gov/api/temporal/daily/point
    • Parámetros: T2M (T media), T2M_MAX, T2M_MIN, PRECTOTCORR (lluvia), community=AG, lat/lon, start/end en AAAAMMDD, format=JSON.
    • Respuesta: properties.parameter.<VAR> indexado por fecha. Faltantes = -999.
    • Elevación de la celda: geometry.coordinates[2] (formato [lon, lat, elev_m]). Es la que se usa para la corrección por altitud del pipeline.
    • CORS: POWER no envía cabeceras CORS → fetch desde el navegador falla aunque el servidor responda. Usa curl o el script Python.
    sin probar

    2. CMR — buscar colecciones

    CORS: variable

    Catálogo de productos Earthdata por palabra clave.

    📖 Cómo funciona
    • Endpoint: cmr.earthdata.nasa.gov/search/collections.json
    • Parámetros: keyword (URL-encoded), page_size.
    • Respuesta: feed.entry[], cada uno con short_name (ej. SPL3SMP_E) y title.
    • CORS: CMR a veces acepta fetch del navegador y a veces lo rechaza por preflight. Si falla aquí, prueba con curl.
    sin probar

    3. CMR — gránulos SMAP

    CORS: variable

    Archivos SPL3SMP_E (humedad del suelo) que cubren tu caja.

    📖 Cómo funciona
    • Endpoint: cmr.earthdata.nasa.gov/search/granules.json
    • Parámetros: short_name=SPL3SMP_E, bounding_box=oeste,sur,este,norte, sort_key=-start_date, page_size=5.
    • Respuesta: feed.entry[] con title y time_start. Si no hay datos en la zona, entry=[].
    • Nota: la caja se calcula con ±0.75° alrededor de tu lat/lon (≈150 km).

    4. CMR-STAC

    CORS: normalmente sí

    Catálogo raíz STAC de NASA (Landsat, HLS, etc.). Sin clave.

    📖 Cómo funciona
    • Endpoint: cmr.earthdata.nasa.gov/stac/
    • Parámetros: ninguno (solo la raíz).
    • Respuesta: objeto STAC con title/id y un array links. Los rel=="child" son proveedores STAC (LPCLOUD, POCLOUD, etc.).
    sin probar

    5. GIBS (WMS) — imagen satelital

    CORS: sí (es imagen)

    Devuelve un PNG de una capa y una fecha. Sin clave.

    📖 Cómo funciona
    • Endpoint: gibs.earthdata.nasa.gov/wms/epsg4326/best/wms.cgi
    • Parámetros: SERVICE=WMS, REQUEST=GetMap, VERSION=1.3.0, LAYERS, CRS=EPSG:4326, BBOX, WIDTH, HEIGHT, TIME.
    • ⚠️ Orden del BBOX en WMS 1.3.0/EPSG:4326: sur,oeste,norte,este (lat,lon) — no lon,lat.
    • Respuesta: imagen image/png. Se puede cargar con <img> sin problema de CORS.
    • Nota: MODIS tiene ~2-3 días de latencia; por eso el probador pide una fecha reciente pero no la de hoy.
    sin probar

    6. Worldview Snapshots — foto de la zona

    CORS: sí (es imagen)

    Foto JPEG de una fecha y zona. Sin clave.

    📖 Cómo funciona
    • Endpoint: wvs.earthdata.nasa.gov/api/v1/snapshot
    • Parámetros: REQUEST=GetSnapshot, LAYERS, CRS=EPSG:4326, TIME, BBOX, FORMAT=image/jpeg, WIDTH, HEIGHT.
    • ⚠️ BBOX: igual que WMS 1.3.0 → sur,oeste,norte,este (lat,lon).
    • Respuesta: imagen image/jpeg. Se inserta con <img>.
    • Diferencia con GIBS: WVS es más simple y suele responder más rápido; GIBS permite más capas y parámetros WMS.
    sin probar

    7. api.nasa.gov — EPIC

    CORS: normalmente sí

    Última imagen de la Tierra vista desde el punto L1. Clave gratuita o DEMO_KEY.

    📖 Cómo funciona
    • Endpoint: api.nasa.gov/EPIC/api/natural
    • Parámetros: api_key=... (DEMO_KEY sirve para probar, pero tiene límite por hora).
    • Respuesta: array de objetos; el primero trae image (nombre del archivo) y date (ISO).
    • URL de la imagen: api.nasa.gov/EPIC/archive/natural/AAAA/MM/DD/png/<image>.png?api_key=...
    sin probar

    8. AppEEARS — catálogo de productos

    CORS: normalmente sí (solo catálogo)

    Lista pública de productos (MODIS, VIIRS, Landsat). Pedir datos reales requiere login Earthdata.

    📖 Cómo funciona
    • Endpoint del catálogo: appeears.earthdatacloud.nasa.gov/api/product (público, sin token).
    • Respuesta: array de objetos con ProductAndVersion y Description.
    • Pedir datos reales: requiere login Earthdata en dos pasos (/api/login devuelve un token Bearer que luego se manda en Authorization). Eso no se puede hacer solo con fetch en un HTML estático.
    • En el pipeline: se usa desde Python con earthaccess (ver tarjeta 10).
    sin probar

    9. FIRMS — incendios activos

    CORS: variable · requiere MAP_KEY

    Detecciones de incendios en los últimos días. Requiere MAP_KEY gratuita.

    📖 Cómo funciona
    • Endpoint: firms.modaps.eosdis.nasa.gov/api/area/csv/{MAP_KEY}/VIIRS_SNPP_NRT/{Area}/{DayRange}
    • MAP_KEY: se pide gratis con tu correo en firms.modaps.eosdis.nasa.gov/api/map_key/.
    • Area: oeste,sur,este,norte · DayRange: días hacia atrás (1–10).
    • Respuesta: CSV. Si la clave es inválida, HTTP 400 con texto Invalid MAP_KEY.
    • Límite: pocas transacciones cada 10 minutos.
    sin probar

    10. Harmony, OPeNDAP y earthaccess

    Requieren login Earthdata

    No se llaman desde el navegador: van desde Python.

    📖 Cómo funciona
    • earthaccess: login con Earthdata, búsqueda por short_name, bounding_box y temporal, y descarga de gránulos a disco.
    • Harmony: servicio OGC para pedir subsetting/reprojection de productos (requiere token Bearer).
    • OPeNDAP: acceso a variables puntuales dentro de un NetCDF/HDF sin descargar todo el archivo.
    pip install earthaccess

import earthaccess
earthaccess.login()   # usuario y contraseña Earthdata
res = earthaccess.search_data(
    short_name="SPL3SMP_E",
    bounding_box=(-77, -10.5, -75.5, -9),
    temporal=("2026-10-01", "2026-10-31"))
print(len(res), "archivos")
earthaccess.download(res[:1], "./datos")
